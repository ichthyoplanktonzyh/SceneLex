# SceneLex MVP 资源验证方案

## 目的

第一轮实验不验证某个学习 App 是否好用，而验证 SceneLex 资源的核心主张：

> 词义边界规格与专门设计的场景证据，能否比翻译或普通图片更好地支持相邻词区分与新场景迁移？

实验输出用于修订义项与场景资源。学习端只记录实验所需数据，不成为 SceneLex 的用户身份权威。

## 第一轮范围

- 6–10 个义项；
- 至少覆盖属性、动作、心理状态、标量/逻辑三类意义；
- 包含 2–3 组中文母语者容易混淆的相邻词；
- 每个义项至少有原型证据、一个边界/对比证据和一个真正改变两个维度的迁移证据；
- 使用连续图片、简单动画或低成本短片，先控制教学变量，不比较影视制作质量。

候选可从下列集合中选取：

```text
messy / dirty
reluctant / hesitant / refuse
almost / barely
```

如果相邻词存在包含或重叠，实验题必须允许 `both`、`insufficient evidence` 等答案，不能为了方便评分制造错误二选一。

## 最小对照

第一轮只设置三个条件，避免样本被过多实验组摊薄：

1. L2 声音 + L1 翻译；
2. L2 声音 + 普通代表图片；
3. L2 声音 + SceneLex 原型、边界与迁移证据。

后续确认有效后，再拆分通用场景、L1 适配场景和个人经验适配场景。

## 测量

所有组使用未在教学阶段出现的测试材料。

- 即时声音—场景匹配正确率；
- 相邻词边界判断，包括允许重叠与证据不足的题目；
- 新人物、新对象和新环境中的迁移正确率；
- 一周后保持率；
- 正确作答反应时；
- 开放输出的目标表达自然度。

每个选择任务必须在资源中提供 `choices` 与 `expected_answer`；开放输出必须提供 `scoring_note`。教学场景中的练习题不能原样充当效果测试题。

## 三层发布门

```text
schema-valid
  → reviewed（语言、语义、场景与教学审核通过）
  → published（来源可追溯，学习任务可评分，迁移证据通过实验或有明确审核记录）
```

结构校验不等于语义正确，专家审核也不等于学习有效。`published` 应保留实验版本、样本范围、指标与结论引用；在对应数据契约落地前，仓库内资源保持 `reviewed`。

## 决策规则

第一轮重点看效应方向和失败模式，不急于宣称普遍有效：

- 如果原型理解提高但迁移无提升，优先重写 transfer 证据；
- 如果迁移提高但相邻词区分无提升，检查 boundary/contrast 是否把重叠误写成互斥；
- 如果只比普通图片略好但成本显著增加，减少固定场景数量；
- 如果某类词持续失败，为该语义类型建立专门场景设计方法，而不是用更多同类视频掩盖问题。

只有当至少一组高价值词义在新材料上表现出稳定迁移信号后，才扩展到 30–50 个义项。
