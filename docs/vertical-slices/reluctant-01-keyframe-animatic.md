**Keyframe Plan 是人工起草的，未经模型生成。** 这是刻意的：本 PR 要回答的问题是
「最少需要几个视觉锚点」，而让模型按角色枚举给每个镜头凑五张关键帧，正是这个原型
要避免的失败模式。工具因此没有 `plan` 子命令，只负责校验、时间轴、预览与展示。

## Selected keyframes

### shot-01（2.5s，`establish_trigger`）— 2 帧

| ID | roles | t | hold | 视觉状态 |
|---|---|---|---|---|
| `shot-01-kf-01` | `initial` | 0.0s | 1.0s | 孩子端坐、双手平放、目光朝前**不在盘子上**；妈妈的手已离桌、正伸向盘子，但尚未指定 |
| `shot-01-kf-02` | `trigger` + `final` | 1.0s | 1.5s | 妈妈手臂完全伸出、食指指向西兰花、眼睛看着孩子并**保持**这个姿势；孩子已低头看向盘子，身体姿态未变 |

**为什么不能删。** 删掉 kf-01，就失去了「孩子的注意力本来不在盘子上」这个基准，
注意力转移不再能被证明是被请求引发的，孩子随后的停顿也可能被读成他本来就在发呆。
删掉 kf-02，请求关系根本不成立。

**状态差异。** 妈妈的手臂（运动中 → 指定并保持）；孩子的视线（朝前 → 落在盘子上）。
身体姿态刻意保持不变——阻力不能在请求成立之前出现。

**为什么不是三帧。** 候选的第三帧是把「妈妈指出」与「孩子看过去」拆开。放弃它的
理由是：kf-01 已经写明孩子的视线不在盘子上，因此 kf-01 → kf-02 的顺序**本身**就
编码了「先有手势，后有注意力」这一因果；再插一帧只会得到两张几乎相同的图。这一帧
同时承担 `trigger` 与 `final`，也正是 schema 用 `roles` 数组而不是单数 `role` 的
唯一真实理由：**为了凑角色枚举去复制画面是错的。**

**结论：shot-01 的 `visual_start` / `visual_end` 直接就够用。**

### shot-02（4.8s，`semantic_climax`）— 5 帧

| ID | roles | t | hold | 视觉状态 |
|---|---|---|---|---|
| `shot-02-kf-01` | `initial` | 0.0s | 0.8s | 更紧的构图；姿态与 shot-01 结尾完全一致，什么都还没动 |
| `shot-02-kf-02` | `trigger` | 0.8s | 1.0s | 已后靠几度、肩膀贴向椅背、双手微微收回；头转开，视线不在食物也不在妈妈身上 |
| `shot-02-kf-03` | `transition` | 1.8s | 1.2s | **伸手停在半途**：手臂伸出约三分之二、手张开悬在桌面上方未触到叉子；躯干没有跟上来，仍然后靠 |
| `shot-02-kf-04` | `semantic_climax` | 3.0s | 1.0s | **叉子已叉起西兰花、举到嘴边停住**；嘴唇闭合未张开；躯干仍然后靠 |
| `shot-02-kf-05` | `final` | 4.0s | 0.8s | 这一口已经吃完；叉子放回盘中；神情平淡、视线朝下；身体**仍然**稍稍后靠 |

**为什么不能删。**

- **kf-01**：跨剪辑点的连续性锚点，也是「什么都没发生」本身的证据。删掉它，画面
  从两人镜头直接跳进「已经后靠」，观众失去衡量停顿长度的基准——而停顿是不情愿
  最先可见的形态。
- **kf-02**：把「停顿」与「走神」区分开的那一帧。身体正在离开被要求的对象。
  删掉它，整段就只剩「慢」，而慢本身不是不情愿。
- **kf-03**：把 reluctant 与普通服从分开的那一帧。从「后靠」直接过渡到「握着叉子」，
  插值与视频模型**都会**生成一次平滑、正常的伸手，中途那半秒会被抹掉——而启动
  延迟是 `must_show` 明写的证据。「身体没有跟上手」也让「只有手在配合」直接可见。
- **kf-04**：全场最强的一帧。第一次停顿只能证明「启动慢」；第二次停顿证明阻力
  **贯穿整个执行过程**。删掉它，整条弧线塌成「犹豫一下然后正常吃」。它同时钉住
  「孩子自己把食物送到嘴边」，与 refuse 划清界限。
- **kf-05**：同时证明动作确实发生并由孩子自己完成（≠ refuse），以及意愿始终没有
  转正（≠ 主动配合）。

**被考虑过但没有单独成帧的候选。** 「握住叉子」「叉起西兰花」都是普通动作，可以
从相邻帧插值，删掉它们不改变任何语义推断。「平淡咀嚼」与 kf-05 的差别只是下颌
位置——若首轮出图看不出「这一口确实吃了」，再补一帧咀嚼比现在先画一张更有依据。

**结论：shot-02 的首尾两帧远远不够。** 两次停顿都是「画面上什么都不发生」的时间，
恰恰是首尾锚点最无法表达、也是视频模型最会自动抹掉的东西。

**总计：7 帧（2 + 5）。** 没有任何一帧是为了凑角色枚举而存在；`initial` 与 `final`
在 shot-01 由同一批帧兼任，`trigger` / `transition` / `semantic_climax` 并不要求
每个镜头都有。

## Timing review

Animatic 揭示的核心问题是**时长**，不是选帧。

### shot-02 的动作预算

把 Shot Plan 的 `action` 逐段拆开，按正常人类动作速度估算（且这段动作被明确要求
**慢于平常**）：

| 动作段 | 需要 |
|---|---|
| 请求发出后的静止 | 0.6–0.8s |
| 后靠 + 视线移开并保持 | 0.8–1.0s |
| 起手到伸手中途 | 0.5s |
| **中途停住**（Shot Plan 原文 `stops halfway for half a second`）| 0.5s |
| 续伸 + 握住叉子 | 0.5s |
| 叉起西兰花 | 0.7–0.9s |
| 举到嘴边 | 0.5s |
| **嘴边再停一次** | 0.4–0.5s |
| 咬 + 咀嚼 + 吞咽 | 1.8–2.5s |
| 放回叉子 | 0.5s |
| 结束后仍后靠的收尾 | 0.5s |
| **合计** | **≈ 7.8–8.5s** |

v04 给了 **4.8s**，缺口约 3 秒。

Animatic 把缺口指到了具体位置：`kf-04 → kf-05` 只有 **1.0s**，而这段要装下嘴边
停顿 + 咬 + 咀嚼 + 吞咽 + 放下叉子（≈ 2.7s）；`kf-03 → kf-04` 只有 **1.2s**，
要装下续伸 + 握住 + 叉起 + 举起（≈ 1.8s）。前半段（静止与后撤，合计 1.8s）反而
是唯一宽裕的部分。

### 七个问题的回答

1. **shot-01 的请求建立得过慢或过快？** 合适。手势在 1.0s 建立，随后 1.5s 是
   **保持等待**——等待本身就是请求的一部分，1.5s 足以被读成「她在等」而不拖沓。
   shot-01 不需要改。
2. **shot-02 的第一次停顿是否有足够时间？** 有。kf-01 与 kf-02 合计 1.8s 覆盖
   「静止 + 后撤并保持」，是这个镜头里唯一时间充裕的段落。
3. **伸手中途停住是否需要独立锚点？** **需要**，见 kf-03。这是本次审核最确定的
   一条结论。
4. **「继续行动」是否从拒绝自然过渡到勉强执行？** 在当前 4.8s 下**会被赶**：
   1.2s 内要完成续伸、握住、叉起、举起，动作会显得果断，反而抹掉前面刚建立的阻力。
   在下面建议的三镜方案里，切点之后以「叉子已在手中、躯干仍后靠」开场，过渡是
   「身体没有跟上手」的延续，而不是从拒绝跳到执行。
5. **动作完成后的低意愿状态是否需要 hold？** 需要，且当前 0.8s 偏短。收尾不足
   约 0.8s 的静止，观众会停在「吃完了」这个动作信息上，读不到「他仍然后靠」。
6. **4.8 秒是否足以承载全部动作？** **不够。** 见预算表。
7. **压缩后是否会失去 reluctant 的慢启动与停顿证据？** **会，而且是必然的。**
   两次停顿是画面上「什么都不发生」的时间，压缩时最先被牺牲；而它们正是
   `semantic_evidence.must_show` 的第 3、4 条。压缩掉它们等于压掉这个场景的判据。

## 2-shot vs 3-shot

```text
RECOMMEND 3 SHOTS
```

**这不是「v04 的拆法错了」，而是「4.8s 装不下 shot-02」。** 两条出路只有两条：

- **压缩动作链** → 停顿被抹掉 → reluctant 退化为「慢」（见问题 7）；
- **延长 shot-02 到约 8s** → 触及 Shot Plan 自己的硬上限（`MAX_SHOT_DURATION = 8.0`，
  且远超 5.0s 的 warning 阈值）。而那条纪律的原话正是：*超过 8 秒说明这个镜头
  其实是两段动作。*

两条路都指向同一个结论。

**切点：孩子握住叉子之后、叉起西兰花之前。**

为什么这是自然动作边界：

- 它是一个**已完成的子动作**（手到位、握住），不是动作中段；
- **两次停顿分别落在切点两侧**——启动停顿在前，嘴边停顿在后。没有任何一次停顿
  被剪辑点破坏，而停顿正是需要保护的东西；
- 切点两侧景别可以不同（前段需要看到身体后撤，后段需要看到手、叉子与嘴的关系），
  这本身就是切镜的正当理由。

**跨镜如何保住状态**（这正是 v02/v03 缺的那一步，不能重犯）：

新 shot-03 的 `visual_start` 必须显式写明——躯干**仍然后靠**、视线**尚未回到**
盘子、叉子已在手中、桌面与盘子的相对位置与人物朝向不变；`must_show` 必须包含
嘴边那次停顿与结束后仍后靠。低意愿不是在剪辑点重新建立，而是被**延续**过去。

**为什么这不是回到「一 Beat 一 Shot」。** 这个切点恰好落在 beat 2 与 beat 3 的
边界上（beat 2 以「伸手去拿叉子，手在半途停了一下」结束）。**这个重合是巧合，
不是依据。** 依据是动作完成度与时长预算：即使 beat 边界划在别处，切点仍然会在
握住叉子之后。判据没有变成「每个 beat 一个镜头」——beat 1 仍然独占 shot-01，
而 shot-01 的 2.5s 与 2 帧完全不需要动。

**与 v02/v03 的关系必须说清楚。** v03 的切点是
`hand holding the fork, fork being brought toward the broccoli` → `child holds fork,
starts to pick up`，与这里建议的位置几乎相同，时长结构（3.0 / 4.0 / 4.0 = 11.0s）
也几乎相同。所以本次结论**不是**「回到 v02/v03」，也**不是**「v04 白做了」：

- v02/v03 的真正不足从来就不是切点，而是没有把状态跨剪辑点写出来——上一轮的
  切片记录已经这样判断过，本次 animatic 证据支持那个判断；
- v04 的价值是逼出了「切镜必须有理由、跨点必须保状态」这条约束，并且证明了合并
  方案在语义上确实成立；
- 现在推翻它的是**时长证据**：合并方案要成立，需要约 8s，而这超出了这一层自己
  的执行纪律。

**哪个方案更适合后续图片与视频生成。** 三镜方案更适合：每个镜头回到 2–5s 的生产
目标区间（约 2.5 / 4.0 / 4.5），每段交给视频模型的动作更少更单一；关键帧密度也
更均匀（约 2 / 3 / 3），不再出现 1.0s 内塞四个动作阶段的段落。

**本 PR 不修改 v04，也不生成 v05。** 这是一条建议，应当由 Shot Plan 层在下一次
编译时执行——上一轮的教训就是「上游问题要在上游修」。

## Silent semantic read

以下是**基于文字状态与时序的推演**，不是真实视觉审核。

- **删除台词后，请求是否仍可理解？** 可以。指向手势 + 注视 + 保持等待 + 盘子就在
  孩子面前，`kf-01 → kf-02` 的注意力转移把因果关系钉住。台词只做自然化补充，
  这与 v04 把它标成 `optional_dialogue` 一致。
- **是否可能被看成 refuse？** 在完整七帧下不会。kf-04（自己把食物送到嘴边）与
  kf-05（叉子放回盘中、动作完成）直接证否。风险只在于 kf-04 被删，或被画成手缩回。
- **是否可能被看成 dislike / disgust？** **这是最大的残余风险，而且静态文字审核
  回答不了它。** 七帧中没有任何一条要求厌恶表情，`must_avoid` 明确禁止皱鼻、干呕、
  头转开躲食物；但「不想吃的蔬菜」这个题材本身会把观众推向挑食解读。判据是：
  阻力必须出现在**身体与动作**（后靠、手停住、身体没跟上手），而不是**脸**。
  **图片阶段必须专门检查这一点。**
- **是否可能只被看成 slow movement？** 单看 kf-03 会。区分它的是 kf-02（视线主动
  回避）与 kf-03 本身（躯干没有跟上手）：慢是均匀的，不情愿是**身体与手不一致**。
- **reluctant 最强的证据帧是哪一张？** `shot-02-kf-04`——动作已经几乎完成，阻力
  仍然在。

```text
这仍是 pre-image review，不等于真实视觉语义审核。
```

文字占位卡能审的是时序、状态覆盖、hold 时长、镜头边界与动作密度；
它**不能**审构图可读性、表情质量、真实画面语义与图片之间的连续性。
`animatic.html` 顶部与每张卡上都标着这一点。

## Blocking

1. **shot-02 的 4.8s 装不下它自己的动作链**（缺口约 3s）。需要一份按三镜结构重编的
   Shot Plan（切点在握住叉子之后），且新 shot-03 必须显式延续躯干后靠、视线未回、
   叉子在手。本 PR 不生成 v05。
2. Shot Plan 更新后，本 Keyframe Plan 需要重新选帧（预计 2 / 3 / 3 结构），
   并重新生成 animatic。

## Non-blocking

- **kf-05 的 0.8s 收尾偏短**，建议 ≥0.8s，三镜方案下可给到 1.0s。
- **咀嚼是否需要独立关键帧**：目前合并进 kf-05。若首轮出图看不出「这一口确实吃了」，
  再补一帧——现在补属于无证据加帧。
- **dislike / disgust 漂移的最终判定必须留给图片阶段**：文字层已经守住
  （`must_avoid` 完整、`must_show` 里没有任何厌恶线索），但真正的检查对象是画面。
- shot-01 无需改动：2 帧、2.5s、hold 1.0 / 1.5 全部成立。

## Deferred

- **图片与视频生成**：本 PR 完全不做。不选模型、不写提示词、不提交任何二进制资产。
- **Keyframe Plan 的 LLM 起草**：第一版刻意人工选帧。是否值得让模型起草，应当在
  有第二、第三条真实样本之后再判断——现在建它就是在为一个还不存在的规模问题投资。
- **图片文件引用字段**：schema 里**没有** `image.path` / `status`。等真的要把图片
  绑定到关键帧时，由后续的 image-generation manifest 按 keyframe ID 绑定，
  而不是现在先在这里挖一个空字段。
- **digest / SHA / 自动 stale 传播 / 依赖 DAG**：本层只做确定性检查（引用的
  Shot Plan 版本目录必须存在）。
- **转场类型**：manifest 里一律写 `cut`，因为 Shot Plan 不描述转场。这不是转场系统。
- **其余场景**：不批量生成，不迁移 legacy render 工具链，不删除旧代码。
- **`data/drafts/renders/v05` / `v06` 里的历史手工关键帧实验**（含 png/mp4）：
  那是 legacy beat-image 原型下的产物，与本层没有关系，本 PR 不迁移也不引用它们。

## 工具与校验

```bash
python3 tools/keyframes.py validate reluctant-01-proto-01
python3 tools/keyframes.py show     reluctant-01-proto-01
python3 tools/keyframes.py animatic reluctant-01-proto-01
python3 tools/keyframes.py list
```

`animatic` 确定性生成两份产物，不调用任何模型：

- `animatic.yaml` — 机器可校验的时间轴（镜头边界、每帧的 start / end / hold、总时长）；
- `animatic.html` — 单文件预览，无 CDN、无服务器、无外部图片，浏览器直接打开；
  可按时间轴播放并高亮当前关键帧。

校验规则见 `tools/keyframe_plan.py`。**刻意没有**规定：每个 Shot 必须有
`initial` + `final`、每个 Shot 必须 2–5 帧、每个 Shot 必须有 `semantic_climax`、
每个 Beat 必须对应关键帧、关键帧数量上限。一个样本不足以把这些写成不变量——
写死它们等于让校验器替内容决定该画几张图。
