# SceneLex — 项目战略文档

> 最后更新：2026-08-02
> 基于 `AGENT.md`、`README.md`、理论总纲与 `docs/production-workflow.md` 提炼

## 1. 产品愿景

构建一个“把词义编译成可体验微世界的语义教学引擎”。核心主张：

> 经验即词义，微世界即体验。

SceneLex 已经从早期的“场景即释义”演进为更底层的认知架构。它不是一个被动播放的媒体库，也不由某个播放器或模型厂商定义。它是一个引擎，能够将抽象的词义范畴实例化为学习者可以沉浸和交互的具体经验。现有的 WordSense、SceneSpec 以及场景证据系统，依然是这个引擎坚实的“语义层基础设施”。

## 2. 核心问题

理论基石：语言是一种符号系统，是对经验世界的符号化编码。词汇是人类对经验进行范畴化后的符号编码。词义的本质是经验的范畴化 + 语言共同体的约定。

传统学习路径常是 `L2 声音 → L2 文字 → L1 翻译 → 概念`，导致语言符号与真实经验脱节。SceneLex 要建立：

```text
L2 声音 → 场景与经验 → 概念
```

让学习者在微世界中体验“在什么经验、状态和关系中会自然使用这个表达”，进而真正内化符号意义，而不是只记翻译。

## 3. 核心原则

1. **词义，不是词头。** 多义词的不同含义是不同教学单位。
2. **经验优先于媒介。** 词义必须被还原为经验（关系、动作、结果），媒介只是经验的呈现载体。
3. **词汇分类决定编译策略。** 10种经验分类（实体、动作、心理等）各自对应不同的微世界类型与呈现模式。
4. **LLM驱动编译。** 放弃形式化描述语言，利用 LLM 的内隐知识处理语义理解与经验维度映射。
5. **语义骨架与表面渲染解耦。** 人物、地点、风格与底层模型不能成为词义的本质条件。
6. **生成不等于发布。** 引擎生成是草稿；人工 promote 决定正式发布与入库。
7. **相邻概念不必互斥。** 包含、重叠、程度和不同维度的易混淆词，必须如实呈现对比经验。
8. **模型按能力适配。** 不同的生成和渲染模型只属于特定微世界类型的实现层，按需调度。
9. **语义优先于审美。** 精美但违背经验范畴和语义边界的呈现必须淘汰。

## 4. 权威边界（三层解耦）

词义（抽象层） → 场景（语义层） → 媒体（呈现层） 的解耦架构：

```text
WordSense + SceneSpec (语义权威：词义与场景证据)
         ↓
经验分类 + 编译策略 (编译引擎：LLM语义理解)
         ↓
微世界构建指令 (呈现层：多媒体渲染与生成)
         ↓
学习者交互 (体验层：教学与验证)
```

- **语义层拥有**：词义、条件、概念关系、L1易混淆词、教学证据（原型/对比/反例/边界/迁移）、学习任务。
- **编译层拥有**：类别特定的编译逻辑、内隐的经验维度映射、微世界蓝图。
- **呈现层拥有**：不同媒介的渲染管线（视频、交互图、3D等）、模型适配和生成参数。
- **体验层拥有**：学习者状态、学习记录、UI、播放与交互节拍。

## 5. 媒体交付策略

媒体生产的目标不再是默认把所有词义做成固定时长的 3D 短片。微世界类型由“经验类别”决定，系统在核心上是媒介不可知（media-agnostic）的：

- **实体型、属性型、空间型**：可能通过单图、对照图或空间交互来体验；
- **动作型、状态变化型**：可能通过短循环、物理模拟或短动画；
- **心理型、意图型、事件逻辑型**：可能具有压力—反应—行动的短片；
- **认知型、时间结构型**：可能通过事件并置、时间线结构或组合表达。

视频（如原有的 Shot Plan/Keyframe/Image/Video 工作流）仅是“视频型微世界”的一种特定实现（Legacy保留），视频不再是唯一媒介。

### 分阶段演进

微世界建设采用分阶段策略：

1. **经验叙事（当前）** — LLM 将 WordSense + SceneSpec 编译为学习者可体验的文本叙事，嵌入背单词软件。
2. **富媒体增强** — 叙事 + 配图 + 音频。
3. **交互微世界** — 按经验类别选择对应引擎（3D / 动画 / 物理交互 / 叙事 / 逻辑推演）。

每个阶段都产生独立的用户价值，前一阶段的产出是后一阶段的输入。

## 6. 编译引擎原则

LLM 作为语义编译器，取代了旧有的单一 Director 角色。不要试图用苍白的形式化语言去穷尽描述词义的方方面面，而应该利用 LLM 在海量人类文本中习得的关于经验世界的内隐知识。

当输入“词汇 + 词汇类别 + 学习者状态”时，LLM 编译器能理解其背后的经验维度，并生成适当的微世界构建指令。这些指令随后交付给不同的渲染引擎进行实体化。这保留了原有设计中“通过场景提供证据”的功能，但赋予了更强、更灵活的多媒介生成能力。

## 7. 内容状态与发布门

维持稳定的工作流与生命周期：
```text
candidate → draft → reviewed → published
```

1. **schema-valid**：语义基础设施结构与仓库不变量通过。
2. **reviewed**：词义范畴、经验场景和教学质量（含 L1 易混淆对比设计）已有可靠审核结论。
3. **published**：微世界呈现物 QC 通过，来源可追溯，学习单元可被交互。

## 8. 当前阶段非目标

- 在经验叙事阶段跳过直接做交互微世界。
- 大规模批量产出或数千词汇的广度扩展；
- 试图用形式化描述语言精确定义每一丝语义（交给 LLM 处理）；
- 将系统绑定于单一媒介（如强制全视频）、单一渲染风格或特定的生成模型；
- 完整自适应学习产品、云同步、多用户与商业化系统建设。
