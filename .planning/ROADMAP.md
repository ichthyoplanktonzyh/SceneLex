## M1：理论框架与系统架构重设计 ⏳

目标：完成理论转向的文档对齐与核心架构重设计，将系统确立为基于 LLM 隐式知识的“语义教学引擎”，将词汇与词汇类别编译为可体验的微世界。

### M1.1 理论文档对齐 ⏳ ← 当前焦点

- [x] 确立“三层解耦”理论（经验的范畴化 → 场景实例化 → 媒体承载）。
- [x] 确立 10 大经验类型的核心地位。
- [x] 明确“LLM 作为语义编译器”的核心角色，放弃形式化描述语言。
- [ ] 全面更新项目核心文档，体现理论转向。

### M1.2 学习单元结构与经验叙事编译器 ⭐ ← 下一焦点

- [x] 确定分阶段演进策略：经验叙事 → 富媒体 → 交互微世界。
- [x] 确定学习单元结构：经验溯源 + 5 场景叙事 + L1 对比 + 自测。
- [x] 确定 10 类经验 → 5 种底层引擎能力的映射。
- [x] 完成 reluctant-01 HTML 原型验证（`prototype/reluctant-demo.html`）。
- [ ] 构建经验叙事编译器：自动将 WordSense + SceneSpec 输入给 LLM，批量生成学习单元。
- [ ] 用已有 4 个词义（reluctant / almost / dirty / messy）验证编译器泛化能力。
- [ ] 定义学习单元输出 Schema（JSON/YAML），让下游 App 可以直接消费。

### M1 退出条件

- 核心文档全面对齐新理论，不再以单一视频生成为主线。
- 微世界构建指令的 Schema 设计完成。
- LLM 作为语义编译器的主要链路跑通。
- 经验叙事编译器能自动为已有 4 个词义生成学习单元。

## M2：规模化经验叙事与富媒体增强 🔒

- 批量生产经验叙事学习单元，覆盖更多词汇。
- 为叙事增加配图和音频，进入富媒体阶段。
- 对接背单词软件或学习 App 作为消费端。

## M3：跨经验类型泛化 🔒

- 扩展对实体型、动作型、状态变化型、心理状态型等不同经验类型的微世界支持。
- 根据各类型特点设计专有的微世界体验机制。
- 验证泛化能力并提炼稳定自动化的构建模式。

## M4：规模化与消费端集成 🔒

- 批量生产不同体验类型的微世界。
- 面向学习者的消费端（播放器、交互式界面等）集成设计。
- 确立资源发布包格式与 API 规范。
