## M1：理论框架与系统架构重设计 ⏳

目标：完成理论转向的文档对齐与核心架构重设计，将系统确立为基于 LLM 隐式知识的“语义教学引擎”，将词汇与词汇类别编译为可体验的微世界。

### M1.1 理论文档对齐 ⏳ ← 当前焦点

- [x] 确立“三层解耦”理论（经验的范畴化 → 场景实例化 → 媒体承载）。
- [x] 确立 10 大经验类型的核心地位。
- [x] 明确“LLM 作为语义编译器”的核心角色，放弃形式化描述语言。
- [ ] 全面更新项目核心文档，体现理论转向。

### M1.2 微世界类型系统与编译器架构 🔒

- [ ] 设计微世界构建指令的结构与格式。
- [ ] 针对不同经验类型，初步设计微世界类型及呈现模式。
- [ ] 重构 LLM 编译器的工作流：输入（词汇 + 类别 + 学习者状态）→ 输出（微世界构建指令）。
- [ ] 设计媒体无关的底层承载层，支持多模态微世界渲染。

### M1 退出条件

- 核心文档全面对齐新理论，不再以单一视频生成为主线。
- 微世界构建指令的 Schema 设计完成。
- LLM 作为语义编译器的主要链路跑通。

## M2：首个微世界纵向切片 🔒

- 选择 10 大经验类型中的一种，完成首个媒体无关的微世界切片。
- 验证 LLM 编译器能否准确根据语义和类型输出构建指令。
- 验证呈现引擎能否正确渲染微世界体验。

## M3：跨经验类型泛化 🔒

- 扩展对实体型、动作型、状态变化型、心理状态型等不同经验类型的微世界支持。
- 根据各类型特点设计专有的微世界体验机制。
- 验证泛化能力并提炼稳定自动化的构建模式。

## M4：规模化与消费端集成 🔒

- 批量生产不同体验类型的微世界。
- 面向学习者的消费端（播放器、交互式界面等）集成设计。
- 确立资源发布包格式与 API 规范。
